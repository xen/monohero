# Monohero 0.3.3

Adds explicit native URL opening for Codex desktop chats that remain unloaded
after `codex queue` accepts their grant. Configure once on macOS:

```sh
monohero configure-wake --opener /usr/bin/open
```

The configured executable receives `codex://threads/EXACT_UUID` once after
message acceptance, opening/selecting the existing chat without another prompt.
Actual claim/finish remain mandatory. Opener failure preserves the accepted
message ID and blocks the queue explicitly; no automatic resending or retries.

The shared setting applies when future chat workers dispatch, including
previously queued jobs using the updated CLI. Running workers and the daemon
are not restarted or modified. The setting can bring the desktop app forward.

Validation: formatting, clippy with warnings denied, 21 tests and release build.
A native-link wake of an unloaded chat was verified on the current macOS host
by observing its actual claim without sending a second message.
