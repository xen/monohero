# 0.4 native dashboard verification

Verified on macOS with Rust 1.99.1 and GPUI Kit 0.9.0. CLI also builds with
Rust 1.81. Native tests use isolated local state; they do not release a project.

- CLI: fmt, clippy with denied warnings, 38 tests, release build.
- Desktop: fmt, clippy with denied warnings, 3 model tests, debug and release builds.
- Actual native release window: queue selection, changing order, attention
  deferral, resume with new identity at the tail, held-tail policy, queue creation
  and confirmed deletion, retained original task labels after resume.
- Closing the window keeps the process alive. A second launcher opens the existing
  window; hidden startup and reopening were exercised. Quitting the dashboard
  leaves the independent queue daemon and its durable jobs alive.
- The macOS tray is created on the main thread without an error. Left-click and
  menu handlers route to the same show event; direct automated menu-bar clicking
  was unavailable in the local computer-use adapter, so that interaction is not
  claimed as visually verified.
- Integration tests cover a configured native monitor detecting live input wait
  through a scripted public RPC peer and allowing the next job to execute. No
  inference requests are made. They also cover stale/unknown status, legacy claims,
  protected-child drain, failed-command inspection, saved goals, and explicit
  adoption of older queued workers without changing their job IDs or arguments.

Live Codex approval/input flags require an explicitly attached owning public
app-server proxy. A separate history reader's notLoaded state does not establish
that the desktop chat stopped. Host connection limitations remain explicit.
